## The tray says "TwoPlacePaste could not start"

Almost always another program already uses port **47821**. Choose **Open the settings file…** in
the tray menu, add or change the `port` value, save, and start the app again:

```json title="desktop.json"
{
  "port": 47822
}
```

## Sync now asks me which way to go

That is expected after the app starts: Windows and macOS do not record when something was copied,
so until the app sees the clipboard change it cannot know which side is newer. Pick **Sync up** or
**Sync down**. See [Syncing](/two-place-paste/guides/sync/#when-sync-now-has-to-ask).

## The badge says "disconnected"

The app cannot reach the relay. It retries on its own with a growing delay.

- Check that the relay's address opens in a browser: `https://tpp.example.com/healthz` should say
  `ok`.
- If you run the relay, check its logs and that your reverse proxy passes WebSockets through. See
  [Reverse proxy](/two-place-paste/self-hosting/reverse-proxy/).

## The app says the group was deleted

Whoever runs the relay deleted your group from its admin page. Nothing more syncs in it, on any of
its devices. To carry on, open **Settings → Leave the group**, then either create a new group with a
new creation link from the relay's admin, or pair with a device that is in another group. On
Android the same message is on the **Sync** screen, and **Leave the group** is in Settings too.

## The app says it refused a new key

When a device is removed, the others get a new group key. Each one checks that the new key was
made from the key it already holds, using data the relay keeps for every key change. If that check
fails, the device keeps its old key and says so; it stops receiving what the others copy.

- **The relay is out of date.** A relay older than the apps cannot hand over what the check needs.
  Whoever runs it updates it ([Upgrading](/two-place-paste/self-hosting/docker/#upgrading)), then reopen the app.
- **A device older than the relay removed someone.** Update every app. On the device that refused
  the key, use **Settings → Leave the group**, then pair it again. Nothing is lost: a new device
  starts with an empty history and reads the store again.
- If neither is the case, the relay offered a key that did not come from one of your devices. Do
  not trust that relay until you know why.

## Something I copied was not uploaded

- Is **Watch the clipboard** on? It is off by default.
- Was it larger than **Upload automatically up to**? Then a notice in the app says so; send it with
  **Upload**.
- Content the app itself put on the clipboard is never uploaded back.
- Is it shown masked on the Sync tab, with a lock? Then it was a password manager's copy or matched
  a [sensitive-content filter](/two-place-paste/guides/sensitive-content/); **Upload** sends it after
  asking. To find which filter, paste a sample into the filter editor's **Test** box.

## Notifications do not appear on macOS

Open **System Settings → Notifications → TwoPlacePaste** and allow notifications. Without them,
**Sync now** from the tray adds **Upload this clipboard** and **Download the latest** to the menu
for a few minutes instead.

## Where are the logs?

The app writes `tppdesktop.log` next to its settings file. It is cleared on start once it passes
2 MB.

| OS | Location |
|---|---|
| Windows | `%APPDATA%\TwoPlacePaste\tppdesktop.log` |
| macOS | `~/Library/Application Support/TwoPlacePaste/tppdesktop.log` |

Logs never contain clipboard content or keys.

## Still stuck?

[Open an issue](https://github.com/Mark7888/two-place-paste/issues/new) with your OS, the app
version (Settings → Updates) and the relevant log lines.
