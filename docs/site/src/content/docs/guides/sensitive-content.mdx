With **Watch the clipboard** on, everything you copy is uploaded — including a password you copy
from a password manager. The desktop app can tell some copies apart and keep them on this computer.
A copy it treats as **sensitive**:

- is **not uploaded automatically**, even with *Watch the clipboard* on;
- is **masked** on the Sync tab;
- asks **"push anyway?"** when you upload it by hand, from the app or from the tray.

Everything here happens on your computer. The relay never learns that a copy was sensitive, and
the mark does not travel to your other devices: an entry you push anyway arrives there like any
other.

## Password managers

Most password managers mark what they copy as private, so that clipboard history and clipboard
tools leave it alone. The app honours those marks:

| OS | What counts as private |
|---|---|
| Windows | The clipboard formats `ExcludeClipboardContentFromMonitorProcessing` and `Clipboard Viewer Ignore`, or `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` set to 0. |
| macOS | The pasteboard types `org.nspasteboard.ConcealedType` and `com.agilebits.onepassword`, and the *transient* and *auto-generated* types of the same convention (`org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType` and older equivalents). |

Many password managers set these, KeePassXC, KeePass and 1Password among them. Browser extensions
cannot: a browser only lets an extension copy plain text, so a password copied from a password
manager's **browser extension** looks like any other copy. Use autofill there instead, or
[pause auto-sync](/two-place-paste/guides/sync/#pausing-auto-sync) for five minutes before copying.
If a copy from your password manager's app is not masked on the Sync tab, add a
[filter](#your-own-filters). Turn this off with **Settings → Sensitive content → Detect password
managers and private copies**. It is on by default.

## Built-in detectors

Detectors recognise common kinds of secrets in copied text. They are fixed: you can only switch
each one on or off.

| Detector | Default | Catches |
|---|---|---|
| **Private keys** | On | PEM, OpenSSH and PGP private key blocks (`-----BEGIN … PRIVATE KEY-----`). |
| **JSON Web Tokens** | Off | Tokens of the form `eyJ….eyJ….…`. |
| **Cloud and API tokens** | Off | AWS, GitHub, GitLab, Slack, Stripe, Anthropic, OpenAI, Google, npm and SendGrid keys, recognised by their prefixes. |
| **Payment card numbers** | Off | 13 to 19 digits, optionally grouped, that pass the card checksum. |
| **IBANs** | Off | Bank account numbers that pass the IBAN checksum. |

## Your own filters

**Settings → Sensitive content → Filters** shows how many filters you have and how many are on.
**Edit…** opens the filter editor:

<Image src={filters} alt="The filter editor with the Custom tab open and a test sample matching two filters" class="screenshot" />

The **Custom** tab holds your filters; **Built-in** holds the detectors above. Each tab has **Turn
all on** and **Turn all off**, which flip every switch on that tab. Nothing is saved until you press
**Save**.

| Kind | Matches when the text… | Example |
|---|---|---|
| **Contains** | has the value anywhere | `confidential` |
| **Starts with** | starts with the value, ignoring spaces and line breaks around it | `vpn:` |
| **Ends with** | ends with the value, ignoring spaces and line breaks around it | `@corp.example` |
| **Regex** | matches the regular expression ([Go RE2 syntax](https://github.com/google/re2/wiki/Syntax)) | `(?i)password\s*[:=]` |
| **Exact match** | is exactly this text, ignoring spaces and line breaks around it | a specific password |

Every filter can apply to **Text** — a copied text of any length — or to a **File name**, for a
copied file (for example *Ends with* `.pem`, or a regex `^id_(rsa|ed25519)$`). Images and the
contents of files are not checked.

- **Ignore case** is on by default for *Contains*, *Starts with* and *Ends with*. A regex ignores
  case with `(?i)`; an exact match is always compared as typed.
- *Starts with* and *Ends with* look at the whole text. To match the start of any line, use a regex
  with `(?m)`, such as `(?m)^token=`.
- A **label** is optional. It is how the app names the filter when it holds a copy back — for
  example *Not uploaded automatically: matches custom filter “Work VPN”*. Without one, it says
  which kind of filter matched (*matches a custom “starts with” filter*). A built-in detector is
  named the same way: *matches built-in filter “Private keys”*.
- The switch at the start of each row turns a filter off without deleting it.

The **Test** box under the tabs checks a sample against your unsaved changes: matching rows are
highlighted, and a tab hiding a match gets a dot. What you type there is never saved.

<Aside type="tip" title="Use Exact match for a literal secret">
	An exact match is the only kind whose text is **not** stored: the app keeps a salted, slow hash
	(argon2id) of it, and the editor shows only that one is saved. Every other filter's value is
	written to the [settings file](/two-place-paste/guides/settings/#the-settings-file) as you typed it.
	An exact match applies to texts up to 1 KB.
</Aside>

## Exporting and importing filters

Filters are kept on each computer. To set up another device of the group with the same ones, export
them on this one and import them there.

**Export all…** in the filter editor exports every custom filter and the on/off setting of every
built-in filter. The export button on a custom filter's row exports just that filter. Either opens:

<Image src={exportDialog} alt="The Export filters dialog, with a name for the store and the Copy to clipboard and Save to Store buttons" class="screenshot" />

- **Save to Store** saves the export as a [Store](/two-place-paste/guides/store/) item, tagged
  *filters*, so it reaches your other devices encrypted like everything else. Leave the name empty
  for one like *Filters: 3 custom, 2 built-in on* or *Filter: Work VPN*. If the store already holds
  the same export, the dialog names that item and offers **Save anyway**, which saves it again under
  the name you gave.
- **Copy to clipboard** puts it on this computer's clipboard, marked private: clipboard history
  skips it, and it is never uploaded on its own.

An export holds each filter's value as you typed it. Exact matches are left out: only a hash of their
text is kept, and it means nothing on another device, so type those again there. Exporting uses the
saved filters, so save your changes first.

On the other device, the quickest way is from the Store tab: open the export's **Preview**, and
**Import filters…** at the right of its *Text* line opens the filter editor straight into the import,
reading the export from the store. Or copy the export — **Copy** on its Store item — and use
**Import…** in the filter editor, which is greyed out until the clipboard holds an export. Either
way, the import shows what it would do:

<Image src={importDialog} alt="The Import filters dialog, listing an updated filter, a new one, one already on the device and one that cannot be imported" class="screenshot" />

| Row | Starts | |
|---|---|---|
| **New** | Ticked | A filter this device does not have. |
| **Update** | Not ticked | The same filter, changed on another device. Ticking it replaces this device's copy. |
| **Already on this device** | — | Nothing to do. Matched by the filter itself, or by what it matches. |
| **Can't import** | — | Says why: a regex that does not compile, a kind of filter from a newer version, no room left. |
| **Turn on** a built-in filter | Ticked | |
| **Turn off** a built-in filter | Not ticked | An import never quietly lowers the protection. |

Imported filters are added to the editor and outlined there. Nothing is saved until you press
**Save**; **Cancel** throws them away again.

## On the Sync tab

A sensitive clipboard is shown masked: its kind, its length and why it is sensitive. The eye button
shows the text, and hides it again; a new copy hides it too.

<Image src={masked} alt="The Sync tab with a masked sensitive clipboard" class="screenshot" />

When *Watch the clipboard* skipped a copy for being sensitive, one line under it says so. Unlike an
entry held back by a size limit, this does not change the tray icon: password copies are frequent,
and an icon that flags each one teaches you to ignore it.

## Pushing it anyway

**Upload**, or a **Sync now** that would upload, asks first:

<Image src={protectedEntry} alt="The dialog asking whether to push a protected entry anyway" class="screenshot" />

**Push anyway** uploads exactly what was on the clipboard when you were asked. If you copy something
else in between, the app asks again about the new copy. The question expires after two minutes.

**Save clipboard** on the [Store](/two-place-paste/guides/store/) tab asks the same way, before
you name the item: **Continue** goes on to the name and tags, **Cancel** saves nothing. It matters
more there: a store item does not expire after 24 hours, but stays until someone deletes it. If you
copy something else while the form is open, **Save** asks again about the new copy. Answering one question does not answer the other — pushing a copy anyway does
not also let it into the store.

From the tray, the same question arrives as a notification with a **Push anyway** button. With
notifications off, a **Push protected entry anyway** item appears in the tray menu for two minutes
instead.

<Aside>
	A pushed entry is encrypted like every other and expires after 24 hours. Your other devices
	receive it as an ordinary entry: if they take what other devices upload, it lands on their
	clipboard.
</Aside>
